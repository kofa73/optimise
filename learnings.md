## What works
- **Replacing intermediate arrays with scalar variables:** Replacing small fixed-size intermediary stack arrays with individual native scalars significantly reduces register spilling and stack memory traffic (e.g., `strip-internal-array-allocations-for-find_gradients-normalizations` yielded ~11.9% improvement).
- **Exploiting mathematical symmetry:** Inlining operations based on spatial or mathematical symmetry can massively reduce operation counts. For instance, `inline-symmetric-convolutions` reduced multiplications from 36 to 16 per channel and eliminated intermediate kernel arrays for an ~11.7% improvement.
- **Compounding multiple near-miss optimizations:** While isolated optimizations might only yield 2-4% improvements individually, combining them can successfully cross the threshold. `compound-near-miss-optimizations` combined memory offsets, inlined accumulation, and skipped redundant math to achieve ~6.2% improvement.
- **Inlining accumulation variables:** Passing an accumulator directly instead of writing to an intermediate stack array (like `derivatives[4]`) effectively reduces L1 memory traffic and helps compound performance gains.
- **Skipping redundant operations via safe outer-loop unswitching:** Moving conditions outside the innermost loops (e.g., checking if orders are isotropic before the inner loop) can prevent inner-loop SIMD breakage while still allowing the skip of expensive computations.
- **Preserving identical floating-point evaluation order:** Ensuring that structural optimizations produce bit-exact matches to the baseline is a strict prerequisite for any successful change to avoid benchmark errors.

## What to avoid
- **Over-merging loops or pairing function calls:** Grouping calls (like `compute_convolution`) into fewer shared loops caused a massive -48.7% regression due to increased register pressure and disrupted SIMD vectorization.
- **Restructuring without operation reduction:** Changes that merely move code around, like `Fused-angle-ex` (which fused angle and exp without eliminating operations), do not outperform the compiler and can cause regressions (e.g., -8.1%).
- **Pre-combining kernel data before convolution:** Altering the mathematical order of floating-point arithmetic, such as pre-combining weighted kernels in `fuse-paired-kernel-convolutions`, breaks bit-exactness and results in benchmark errors.
- **Inner-loop branching to skip work:** Guarding expensive math (like `expf` or zero speed checks) with `if` statements inside the innermost pixel loop breaks SIMD vectorization. `copy-matched-anisotropy-c2-to-skip-expf` and `skip-zero-speed-orders` regressed by ~1%; `skip-exp-for-isotropic-orders` gained only +1.9-3.2%, insufficient to cross the 5% threshold.
- **Single-instruction algebraic micro-substitutions:** Removing a multiply (`eliminate-gradient-halving` at -0.1%), replacing additions with trig identities (`simplify-b22-trace-identity` at +2.2%), or reusing squared terms (`compute-cos2-sin2-cos-sin-directly` at +3.5%) saves too few instructions to overcome the 5% threshold, as memory/cache bounds dominate.
- **Merging separate passes into existing loops:** Folding a standalone loop (e.g., variance regularization) into the output loop (`merge-variance-regularization-into-output-loop` at -1.0%) can increase register pressure and hurt SIMD scheduling, even when the merged body is small.
- **Inlining array construction without reducing total work:** Inlining the 9-element kernel matrix instantiation (`rewrite-9-element-kernel-matrix-instantiation`) failed to improve performance because the same amount of computation and storage was ultimately required.
- **Relying solely on eliminating one set of stack arrays:** Eliminating just the neighbor pixel arrays via offset access (`inline-neighbor-pixel-access`, `eliminate-intermediate-stack-arrays`) gave only 2.6-4.0% improvement, proving insufficient without being combined with other changes.
