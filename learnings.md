## What works
- **Replacing intermediate arrays with scalar variables:** Replacing small fixed-size intermediary stack arrays with individual native scalars significantly reduces register spilling and stack memory traffic (e.g., `strip-internal-array-allocations` yielded ~11.9%, from 280.6s to 247.3s).
- **Exploiting mathematical symmetry:** Inlining operations based on spatial or mathematical symmetry can massively reduce operation counts. `inline-symmetric-convolutions` reduced multiplications from 36 to 16 per channel and eliminated intermediate kernel arrays (~11.7%, from 317.7s to 280.6s).
- **Compounding multiple near-miss optimizations:** Individual optimizations yielding 2-4% can cross the 5% threshold when combined. `compound-near-miss-optimizations` fused memory offsets + inlined accumulation + skipped isotropic expf (~6.2%, from 247.3s to 232.0s). The three components individually scored +2.6-4.0%, +2.3-3.3%, and +3.9%.
- **Targeting stack array elimination as the primary lever:** All three successful experiments (symmetric convolutions, scalar replacement, compound) share one structural theme: removing intermediate arrays from the innermost loop body to reduce register spilling. This is the dominant bottleneck in this code.
- **Outer-loop unswitching for skipping expensive math:** Moving invariant conditions (e.g., isotropic checks) outside the row loop avoids inner-loop SIMD breakage. This contributed +3.9% individually and was key to the compound success.
- **Preserving bit-exact floating-point evaluation order:** Any change that alters FP arithmetic order risks benchmark errors. All successful experiments maintained identical evaluation sequences.

## What to avoid
- **Over-merging loops or pairing function calls:** Grouping `compute_convolution` calls into fewer shared loops caused -48.7% regression from increased register pressure and disrupted SIMD vectorization (`pair-4-compute_convolution-calls`).
- **Restructuring without operation reduction:** Changes that merely move code around (e.g., `Fused-angle-ex` fused angle+exp without eliminating ops) regressed -8.1%. The compiler already optimizes straightforward code well.
- **Pre-combining kernel data before convolution:** Altering FP arithmetic order (e.g., pre-combining weighted kernels in `fuse-paired-kernel-convolutions`) breaks bit-exactness → benchmark error.
- **Inner-loop branching to skip work:** Guarding expensive math with `if` inside the pixel loop breaks SIMD. `copy-matched-anisotropy-c2-to-skip-expf` regressed -1.1%; `skip-zero-speed-orders` regressed -1.0%; `skip-exp-for-isotropic-orders` gained only +1.9-3.2%, all below threshold.
- **Single-instruction algebraic micro-substitutions:** Removing one multiply (`eliminate-gradient-halving` -0.1%), trig identity substitution (`simplify-b22-trace-identity` +2.2%), or reusing squared terms (`compute-cos2-sin2-cos-sin-directly` +3.5%) saves too few instructions. Memory/cache bounds dominate at this scale.
- **Merging separate passes into existing loops:** Folding variance regularization into the output loop (-1.0%) increased register pressure and hurt SIMD scheduling, even though the merged body was small.
- **Inlining array construction without reducing total work:** Inlining kernel matrix instantiation (`rewrite-9-element-kernel-matrix-instantiation`) failed because the same computation and storage was still required.
- **Partial stack array elimination without compounding:** Eliminating only neighbor pixel arrays (+2.6-4.0%) or only derivative arrays (+2.3-3.3%) individually fell short of the 5% threshold. These only succeeded when combined together with skipped isotropic expf.
