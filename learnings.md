## What works
- **Replacing intermediate stack arrays with scalar variables:** Eliminating small array allocations within innermost loops reduces register spilling and L1 memory traffic (e.g., `strip-internal-array-allocations-for-find_gradients-normalizations` yielded ~11.9% improvement).
- **Exploiting mathematical symmetry to inline logic:** Leveraging spatial symmetries to inline convolutions algebraically instead of expanding arrays reduces multiply-accumulate operations and avoids intermediate allocations (e.g., `inline-symmetric-convolutions` yielded ~11.7% improvement).
- **Outer-loop unswitching for invariant conditions:** Evaluating conditions outside innermost loops safely skips heavy per-pixel math (e.g., bypassing angle math for isotropic orders) without introducing SIMD-breaking branches (`outer-loop-unswitch-isotropic-math` yielded ~6.4% improvement).
- **Compounding multiple near-miss optimizations:** Individually minor structural improvements (like inline accumulation or scalar memory offsets) can collectively cross benchmark thresholds when fused together (`compound-near-miss-optimizations` yielded ~6.2% improvement).
- **Fetching specific pixels inline via direct memory offsets:** Relying on the L1 cache for redundant localized reads instead of bulk stack-allocated intermediate arrays reduces stack memory traffic and register spilling.

## What to avoid
- **Fusing distinct loops into massive single passes:** Combining too many operations into one channel loop (e.g., `inline-scalar-expf-fuse-all-pixel-passes` regressed -114.4%, and `pair-4-compute_convolution-calls` regressed -48.7%) drastically increases peak register pressure and destroys instruction scheduling.
- **Deferring math or using scoped blocks to reduce live variables:** Restructuring logic purely to limit live arrays (e.g., `defer-symmetric-combinations` regressed -91.7%, `phase-gradient-laplacian-into-scoped-blocks` regressed -4.0%) often introduces cache overhead or redundant L1 reads that outweigh the register benefits.
- **Inner-loop branching to skip work:** Adding conditional checks inside hot pixel loops breaks SIMD vectorization and causes overhead that negates the skipped computation. Unswitch at the outer loop instead.
- **Altering bit-exact floating-point evaluation order:** Optimizations that change the sequence of accumulation or omit mathematical terms (like the failed `skip zero speed orders` approach) can introduce subtle correctness bugs and should be avoided. Structural changes must preserve identical mathematical evaluation.
- **Merging lightweight output loops with heavy operations:** Combining simple passes with heavier logic (e.g., `merge-variance-regularization-into-output-loop` regressed -2.4%) disrupts the optimization of the simple loop without reducing overall latency.
- **Minor mathematical simplifications without memory reduction:** Stripping constant scaling factors alone (e.g., `eliminate-gradient-halving`) fails to reach performance targets, as the inner loop is typically bounded by memory traffic and register pressure rather than pure ALU operations.
- **Complex mathematical fusions:** Fusing trigonometric calculations and exponentials (e.g., `Fused-angle-ex` regressed -8.1%) increases critical path dependencies, underperforming native operations.
