## What works
- **Replacing intermediate stack arrays with scalar variables:** Eliminating small array allocations within innermost loops reduces register spilling and L1 memory traffic (e.g., `strip-internal-array-allocations-for-find_gradients-normalizations` yielded ~11.9% improvement).
- **Exploiting mathematical symmetry to inline logic:** Leveraging spatial symmetries to inline convolutions algebraically instead of expanding arrays reduces multiply-accumulate operations and avoids intermediate allocations (e.g., `inline-symmetric-convolutions` yielded ~11.7% improvement).
- **Outer-loop unswitching for invariant conditions:** Evaluating conditions outside innermost loops safely skips heavy per-pixel math (e.g., bypassing angle math for isotropic orders) without introducing SIMD-breaking branches (`outer-loop-unswitch-isotropic-math` yielded ~6.4% improvement).
- **Compounding multiple near-miss optimizations:** Individually minor structural improvements (like inline accumulation or scalar memory offsets) can collectively cross benchmark thresholds when fused together (`compound-near-miss-optimizations` yielded ~6.2% improvement).
- **Altering floating-point accumulation order:** Refactoring math that changes the operation sequence may change results subtly, BUT it's OK to alter numerical results, as long as the changes are tiny. Cheap integration tests are in place that reliably catch such errors and cause a safe rollback, so do not try to avoid them. ROUGH approximations are FORBIDDEN, minor numerical issues either do not result in a visually altered image (and are therefore acceptable), or quickly and reliably caught by integration (regression) tests.

## What to avoid
- **Inner-loop branching to skip work:** Adding conditional checks inside hot pixel loops (e.g., `skip-zero-speed-orders`, `copy-matched-anisotropy-c2-to-skip-expf`) breaks SIMD vectorization and causes overhead that negates the skipped computation.
- **Merging sequential loops or independent passes:** Combining distinct loop bodies (like `pair-4-compute_convolution-calls` which regressed heavily, or `merge-variance-regularization-into-output-loop`) drastically increases register pressure and destroys instruction scheduling.
- **Computing trigonometric ratios directly from squared magnitude:** Trying to substitute functions directly (e.g., `compute-cos2-sin2-cos-sin-directly`) can increase critical path dependencies and fails to map efficiently compared to native scaling.
- **Flattening permutation loops:** Explicitly unrolling or flattening sequential memory gathers (`replace-nested-coordinate-permutation-loops-with-flattened-sequential-memory-gathers`) introduces overhead or suboptimal instruction scheduling, failing to outperform the compiler's native unrolling.
- **Code restructuring without operation reduction:** Fusing expressions, rewriting matrix initializations (`rewrite-9-element-kernel-matrix-instantiation`), or substituting matrix trace identities (`simplify-b22-trace-identity`) often regresses performance by disrupting the compiler's existing optimizations.
