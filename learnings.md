## What works
- **Replacing intermediate stack arrays with native scalar variables:** Eliminating small array allocations within innermost loops reduces register spilling and L1 memory traffic (e.g., `strip-internal-array-allocations-for-find_gradients-normalizations` yielded ~11.9% improvement).
- **Exploiting mathematical symmetry to inline logic:** Leveraging spatial symmetries to inline convolutions algebraically (instead of expanding kernels into large arrays) reduces operations and intermediate allocations (e.g., `inline-symmetric-convolutions` yielded ~11.7% improvement).
- **Outer-loop unswitching for invariant conditions:** Evaluating conditions outside innermost loops safely skips heavy per-pixel math without introducing SIMD-breaking branches (e.g., bypassing angle math for isotropic orders in `001-outer-loop-unswitch-isotropic-math` yielded ~6.4% improvement).
- **Compounding multiple near-miss optimizations:** Grouping structurally related minor improvements (like inline accumulation, scalar memory offsets, and skipping redundant math) into a single unified loop simplification can cross benchmark thresholds collectively (`2026-03-16-00-01-55-compound-near-miss-optimizations` yielded ~6.2% improvement).
- **Fetching specific pixels inline via direct memory offsets:** Fetching pixels directly from source pointers via pre-computed offsets is faster than bulk copying into intermediate stack-allocated matrices (e.g., `000-inline-neighbor-pixel-access` successfully eliminated 72 float allocations per pixel).

## What to avoid
- **Fusing distinct loops into massive single passes:** Combining too many operations into one channel loop drastically increases peak register pressure and destroys instruction scheduling (e.g., `2026-03-16-11-24-58-inline-scalar-expf-fuse-all-pixel-passes` regressed by -114.4%, and `010-pair-4-compute_convolution-calls` regressed by -48.7%).
- **Deferring math or using scoped blocks to reduce live variables:** Restructuring logic purely to limit live arrays often introduces cache overhead or redundant L1 reads that outweigh the register benefits (e.g., `2026-03-17-21-48-08-defer-symmetric-combinations` regressed by -91.7%, `2026-03-16-07-58-50-phase-gradient-laplacian-into-scoped-blocks` regressed by -4.0%).
- **Inner-loop branching to skip work:** Adding conditional checks inside hot pixel loops breaks SIMD vectorization and causes overhead that negates the skipped computation. Always unswitch at the outer loop instead.
- **Altering bit-exact floating-point evaluation order:** Optimizations that change the sequence of accumulation or omit mathematical terms (like skipping zero speed orders where 0×NaN ≠ 0) can introduce subtle correctness bugs. Structural changes must preserve identical mathematical evaluation.
- **Merging lightweight output loops with heavy operations:** Combining simple passes with heavier logic disrupts the optimization of the simple loop without reducing overall latency (e.g., `000-merge-variance-regularization-into-output-loop` regressed by -2.4%).
- **Minor mathematical simplifications without memory reduction:** Stripping constant scaling factors alone fails to reach performance targets. The inner loop is memory/register bounded, so saving a few ALU multiplications (e.g., `000-eliminate-gradient-halving`, `007-remove-0.5-scaling`, `008-remove-0.5-central-difference-scaling`) yields negligible gains.
- **Direct derivation from complex magnitudes without normalization:** Attempting to compute ratios (like cos²θ) directly from squared gradients instead of normalized magnitudes fails to hit performance targets (e.g., `002-compute-cos2-sin2-cos-sin-directly`).
- **Complex mathematical fusions:** Fusing trigonometric calculations and exponentials increases critical path dependencies and underperforms native independent operations (e.g., `002-Fused-angle-ex` regressed by -8.1%).
