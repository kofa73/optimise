## What works
- **Replacing intermediate arrays with scalar variables:** Replacing small fixed-size intermediary stack arrays with individual native scalars significantly reduces register spilling and stack memory traffic (e.g., `strip-internal-array-allocations` yielded ~11.9%, from 280.6s to 247.3s).
- **Exploiting mathematical symmetry:** Inlining operations based on spatial or mathematical symmetry can massively reduce operation counts. `inline-symmetric-convolutions` reduced multiplications from 36 to 16 per channel and eliminated intermediate kernel arrays (~11.7%, from 317.7s to 280.6s).
- **Compounding multiple near-miss optimizations:** Individual optimizations yielding small gains can cross the 5% threshold when combined. `compound-near-miss-optimizations` fused memory offsets, inlined accumulation, and skipped isotropic expf (~6.2%, from 247.3s to 232.0s).
- **Outer-loop unswitching for skipping expensive math:** Moving invariant conditions outside the innermost loop avoids inner-loop SIMD breakage while safely bypassing heavy per-pixel math. For instance, `outer-loop-unswitch-isotropic-math` successfully skipped gradient/laplacian math for isotropic orders, yielding ~6.4% improvement (from 231.9s to 217.2s).
- **Targeting stack array elimination as the primary lever:** Successful experiments (symmetric convolutions, scalar replacement, compound optimizations) share one structural theme: removing intermediate arrays from the innermost loop body to reduce register spilling. This is the dominant bottleneck in this code.

## What to avoid
- **Over-merging loops or pairing function calls:** Grouping `compute_convolution` calls into fewer shared loops caused a huge regression (-48.7%) from increased register pressure and disrupted SIMD vectorization (`pair-4-compute_convolution-calls`).
- **Merging separate passes into existing loops:** Folding variance regularization into the output loop (-1.0%) increased register pressure and hurt SIMD scheduling, despite the small loop body.
- **Restructuring without operation reduction:** Changes that merely move code around (e.g., `Fused-angle-ex` fused angle+exp without eliminating ops, or flattened sequential memory gathers -0.3%) regress or fail to improve performance. The compiler already optimizes straightforward code well.
- **Pre-combining kernel data before convolution:** Altering floating-point arithmetic order (e.g., pre-combining weighted kernels in `fuse-paired-kernel-convolutions`) breaks bit-exactness and leads to benchmark errors.
- **Inner-loop branching to skip work:** Guarding expensive math with `if` checks inside the pixel loop breaks SIMD. Examples like `copy-matched-anisotropy-c2-to-skip-expf` (-1.1%) and `skip-zero-speed-orders` (-1.0%) show that the branching overhead outweighs the skipped work.
- **Single-instruction algebraic micro-substitutions:** Removing one mathematically unnecessary multiply (like the 0.5f scaling factor in `eliminate-gradient-halving`, -0.1%) saves too few instructions. Memory bounds and register pressure dominate at this scale.
- **Inlining array construction without reducing total work:** Rewriting matrix instantiation (`rewrite-9-element-kernel-matrix-instantiation`) failed because the same underlying computation and storage were still required.
