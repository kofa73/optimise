## What works
- **Eliminating intermediate stack arrays via direct memory fetches:** Replacing large read-only array allocations with direct fetches or localized scalars prevents register spilling and reduces L1 traffic. This is the single strongest optimization lever in this codebase (`strip-internal-array-allocations` ~11.9%, `compound-near-miss-optimizations` ~6.2%).
- **Algebraic inlining and mathematical simplification:** Bypassing generalized arrays/matrices to inline convolutions directly using kernel symmetries drastically reduces instruction count. Algebraic decompositions (e.g., anisotropic tensor into isotropic base + correction) also yield gains (`inline-symmetric-convolutions` ~11.7%, `decompose-anisotropic-to-isotropic-base-and-correction` ~1.7%, `inline-isotropic-convolutions` ~1.2%).
- **Nontemporal (streaming) stores for write-once buffers:** Using nontemporal stores for large buffers not immediately reread avoids cache write-allocate pollution (`nontemporal-hf-writes-in-decomposition` ~7.3%, `nontemporal-output-stores` ~1.3%). But never for buffers consumed in the next pass — see "What to avoid."
- **Outer-loop unswitching for heavy math and function-level pass skipping:** Unswitching binary conditions outside the pixel loop to skip expensive `sqrtf`/divisions/`expf` is highly effective, as is skipping entire image passes when scale weights are negligible (`outer-loop-unswitch-isotropic-math` ~6.4%, `skip-hf-decomposition-for-negligible-scales` ~5.0%, `outer-unswitch-zero-speed-order-pairs` ~2.8%, `skip-pde-negligible-norm` ~2.0%). The saved work must be substantial per-pixel (not just a single multiply).
- **Structured specialization via shared `always_inline` helpers:** Factor the heavy pixel/row body into inline functions, but keep `DT_OMP_FOR()` in small per-specialization wrapper functions so the outlined OpenMP worker still sees literal flags. Never move `DT_OMP_FOR()` into a generic helper that takes hot-path flags as parameters — the compiler loses compile-time specialization.
- **Pre-combining matched parameters and absorbing scaling factors:** Pre-summing matched LF+HF stencil sums or absorbing constant factors into loop-invariant constants reduces per-pixel ALU (`precombine-stencil-sums-for-matched-orders` ~3.0%, `peel-column-loop-to-eliminate-clamping` ~2.4%, `compute-cos2-sin2-directly` ~2.3%, `remove-0.5-scaling` ~1.5%).
- **Compounding structurally related near-miss optimizations:** Combining optimizations that target the same bottleneck (e.g., multiple stack array eliminations) can unlock gains where each failed individually (`compound-near-miss-optimizations` ~6.2%).

## What to avoid
- **Altering the `expf` boundary or manually scalarizing SIMD state:** Moving, inlining, or scalarizing `dt_vector_exp`, or explicitly unrolling core accumulation arrays, catastrophically breaks compiler vectorization (`inline-expf-evaluation-anisotropy` -170.9%, `inline-scalar-expf` -114.4%, `explicit-scalarization-of-accumulation-arrays` -111.8%).
- **Dynamic inner-loop branches or per-pixel conditionals:** Skipping operations based on per-pixel conditions (`if (speed == 0)`), evaluating opacity, or copying matched results with inner-loop branches severely degrades SIMD efficiency (`defer-symmetric-combinations` -91.7%, `copy-matched-anisotropy-c2` -83.7%, `skip-zero-speed-orders` -82.4%).
- **Incorrect nontemporal/temporal store placement:** Streaming stores for LF/blur buffers consumed immediately in the next scale cause -68.8% regression. Conversely, reverting intermediate PDE outputs to temporal stores also regresses -6.0%. Match store type to actual reuse distance.
- **Fusing distinct `for_each_channel` loops:** Merging multiple sequential loops into one massive body spikes register pressure and causes heavy stack spilling (`pair-4-compute_convolution-calls` -48.7%, `fuse-variance-regularization` -8.2%).
- **Disrupting hardware prefetcher access patterns:** Removing linear row progression, altering row bound calculations, cache-blocking vertical strips, or adding software prefetch hints ruins L1/L2 throughput (`remove-dwt-interleave-rows` -30.1%, `unswitch-row-bounds` -26.7%, `cache-block-pde-column-strips` -12.4%).
- **Outer-loop unswitching for lightweight savings:** Duplicating macro blocks to skip a single multiply, mask check, or small redundant array bloats instruction cache, negating the minor ALU savings (`outer-loop-unswitch-matched-anisotropy` -17.1%, `outer-unswitch-zero-lf-contribution` -15.4%, `outer-unswitch-zero-sharpness` -13.1%).
- **Micro-optimizing ALU with manual fast-math:** Replacing standard operations with `rsqrt`, explicit FMA chains, inverse-magnitude multiplications, or algebraic rearrangements generally outsmarts the compiler (`unify-direct-neighbor-sums` -7.9%, `algebraically-simplify-anisotropic-accumulation` -7.3%, `extract-inverse-c2` -4.4%, `explicit-fmaf-variance-chain` -2.2%).
- **Reordering or interleaving memory loads:** Interleaving LF/HF loads or reordering computation blocks (swapping sum and angle loops) disrupts the compiler's native scheduling (`phase-gradient-laplacian` -4.0%, `interleave-lf-hf-neighbor-loads` -3.5%).
- **Eliminating small setup overheads:** Buffer pooling, hoisting scale parameters, removing dead code, or deferring mask allocation provides negligible speedup — setup time is invisible against billion-pixel processing (`allocate-contiguous-hf-buffer-pool` -5.1%, `hoist-omp-parallel-across-scales` -2.7%, all 0% improvements for: `precompute-scale-parameters`, `remove-dead-convolution-matrix-generators`, `defer-mask-allocation`).
- **Leaving stale comments or creating large unswitched macro duplication:** When code changes, all comments describing old behaviour must be updated or deleted. Repeated code from unswitching must be factored into `always_inline` functions. Never collapse many unswitched entry paths into one runtime-dispatched parallel loop.
