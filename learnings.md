## What works
- **Replacing intermediate stack arrays with native scalar variables:** Eliminating array allocations within innermost loops reduces register spilling and L1 memory traffic. This is the single most reliable optimization lever — all three largest wins share this pattern (`strip-internal-array-allocations` ~11.9%, `inline-symmetric-convolutions` ~11.7%, `compound-near-miss-optimizations` ~6.2%).
- **Exploiting mathematical symmetry to inline logic:** Leveraging spatial symmetries to inline convolutions algebraically (instead of expanding kernels into arrays) reduces both operations and intermediate allocations (`inline-symmetric-convolutions` ~11.7%).
- **Outer-loop unswitching for simple, binary mathematical variants:** Evaluating a single boolean condition outside the innermost loop to select between two fully specialized loop bodies safely skips heavy per-pixel math without SIMD-breaking branches (`001-outer-loop-unswitch-isotropic-math` ~6.4%). Only works when the condition is simple and the skipped work is substantial (angle math, expf).
- **Compounding multiple structurally related near-miss optimizations:** Grouping 2-3 individually marginal improvements that all reduce the same bottleneck (stack arrays / memory traffic) into one unified change successfully compounds gains (`compound-near-miss-optimizations` ~6.2%).
- **Eliminating redundant math via algebraic absorption into pre-computed constants:** Removing per-pixel scaling factors by absorbing them into loop-invariant constants works when it genuinely eliminates operations rather than just reshuffling them (`remove-0.5-scaling` ~1.5%, `compute-cos2-sin2-directly` ~2.3%).
- **Peeling column loops to remove boundary clamping:** Splitting the column loop into edge/center regions eliminates MAX/MIN from the hot center path (`peel-column-loop` ~2.4%). Works because it removes instructions from the critical path, not because of branch prediction.

## What to avoid
- **Fusing distinct loops into massive single passes:** Combining too many operations into one channel loop drastically increases peak register pressure and destroys instruction scheduling. The worst regressions in the entire experiment history follow this pattern (`inline-scalar-expf-fuse-all-pixel-passes` -114.4%, `pair-4-compute_convolution-calls` -48.7%, `defer-symmetric-combinations` -91.7%).
- **Inlining expf or moving it between loops:** Any attempt to change when/where `expf`/`dt_vector_exp` is evaluated causes catastrophic regression. The compiler's current placement is optimal (`inline-expf-evaluation-anisotropy` -170.9%, `inline-scalar-expf-fuse` -114.4%).
- **Skipping work based on dynamic runtime conditions inside the pixel loop:** Attempting to skip iterations or math based on runtime values (speeds, anisotropy matches) creates control flow or data dependencies that severely degrade SIMD performance (`skip-zero-speed-orders` -82.4%, `copy-matched-anisotropy-c2` -83.7%, `force-isotropic-path-for-zero-speed` -3.4%).
- **Micro-optimizations to the existing hot-path algebra:** Extracting common subexpressions, computing inverse magnitudes, baking factors into arrays, pre-multiplying constants — these all consistently regress by 2-5%, likely disrupting the compiler's vectorization or instruction scheduling (`extract-inverse-c2` -4.4%, `bake-half-factor` -4.5%, `pre-multiply-isotropic-kernel-constants` -3.3%, `replace-angle-divisions-with-inverse-magnitude` -2.6%, `precompute-reciprocal-variance` -3.1%).
- **Eliminating local arrays the compiler already handles well:** Removing stack arrays that are small and well-aligned (like center pixel arrays, sin²θ arrays) via direct computation or formula rewriting doesn't help — the compiler already maps these to vector registers (`eliminate-center-pixel-stack-arrays` +0.1%, `eliminate-sin-theta-sq-arrays` -0.5%).
- **Outer-loop unswitching for complex or marginal conditions:** Unswitching works only for simple binary conditions with substantial skipped work. Unswitching `has_mask`, zero-speed overrides, or adding epsilon to avoid ternaries all regress (`outer-loop-unswitch-has-mask` -3.5%, `eliminate-angle-ternary-with-epsilon` -0.9%).
- **Reordering loops or merging lightweight passes:** Swapping the order of sums vs angle computation, or merging variance regularization into the output loop, consistently fails to help and often regresses (`swap-sums-angle-loop-order` +0.1%, `merge-variance-regularization` -3.2%).
- **Removing zero-initializations of loop-local arrays:** Eliminating `= { 0.f }` initializers disrupts compiler vectorization assumptions (`eliminate-redundant-array-zeroing` -0.2%).
- **Minor algebraic identity substitutions without memory reduction:** Simplifying `b22` via trace identity or similar rewrites yields negligible gains because the inner loop is memory/register bounded, not ALU-bound (`simplify-b22-trace-identity` -0.8%, `skip-cross-corner-isotropic` -0.2%).
