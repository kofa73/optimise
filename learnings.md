## What works
- **Replacing intermediate stack arrays with native scalar variables:** Eliminating array allocations within innermost loops reduces register spilling and L1 memory traffic. This is the single most reliable optimization lever (`strip-internal-array-allocations` ~11.9%, `compound-near-miss-optimizations` ~6.2%).
- **Exploiting mathematical symmetry to inline logic:** Leveraging spatial symmetries to inline convolutions algebraically (instead of expanding kernels into arrays) reduces both operations and intermediate allocations (`inline-symmetric-convolutions` ~11.7%).
- **Outer-loop unswitching for simple, binary mathematical variants:** Evaluating a single boolean condition outside the innermost loop to select between two fully specialized loop bodies safely skips heavy per-pixel math without SIMD-breaking branches (`outer-loop-unswitch-isotropic-math` ~6.4%). Only works when the skipped work is substantial (e.g. sqrt, division, trig) and the condition is a simple compile-time-evaluable boolean.
- **Compounding multiple structurally related near-miss optimizations:** Grouping 2-3 individually marginal improvements that all reduce the same bottleneck (stack arrays / memory traffic) into one unified change successfully compounds gains (`compound-near-miss-optimizations` ~6.2%).
- **Eliminating redundant math via algebraic absorption into pre-computed constants:** Removing per-pixel scaling factors by absorbing them into loop-invariant constants works when it genuinely eliminates operations rather than just reshuffling them (`remove-0.5-scaling` ~1.5%, `compute-cos2-sin2-directly` ~2.3%).
- **Peeling the PDE column loop to remove boundary clamping:** Splitting the column loop into edge/center regions eliminates MAX/MIN from the hot center path (`peel-column-loop` ~2.4%). Only proven to work in the PDE solver's inner loop — peeling the bspline horizontal pass caused -16.7% regression.
- **Nontemporal (streaming) stores for write-once output buffers:** Replacing normal stores with nontemporal writes for output data that is not read again until the next pass avoids write-allocate cache pollution and keeps L1/L2 available for input data (`nontemporal-output-stores` ~1.3%).

## What to avoid
- **Fusing distinct loops into massive single passes:** Combining too many operations into one channel loop drastically increases peak register pressure and destroys instruction scheduling (`inline-scalar-expf-fuse-all-pixel-passes` -114.4%, `pair-4-compute_convolution-calls` -48.7%, `defer-symmetric-combinations` -91.7%).
- **Inlining expf or moving it between loops:** Any attempt to change when/where `expf`/`dt_vector_exp` is evaluated causes catastrophic regression (`inline-expf-evaluation-anisotropy` -170.9%, `Fused-angle-ex` -8.1%). The compiler's current placement is optimal; the loop boundary between c2 computation and convolution accumulation is load-bearing.
- **Skipping work based on dynamic runtime conditions inside the pixel loop:** Attempting to skip iterations or math based on runtime values (speeds, anisotropy matches) creates control flow or data dependencies that severely degrade SIMD performance (`skip-zero-speed-orders` -82.4%, `copy-matched-anisotropy-c2` -83.7%, `force-isotropic-path-for-zero-speed` -3.4%).
- **Outer-loop unswitching for complex or structural states:** Unswitching works only for simple binary conditions with substantial skipped per-pixel math. Unswitching complex state (like `has_mask` -3.5%, `matched-anisotropy` -17.1%, `unswitch-row-bounds` -26.7%) creates massive code duplication that destroys compiler optimization passes or cache locality.
- **Micro-optimizations to the existing hot-path algebra:** Extracting common subexpressions, computing inverse magnitudes, baking factors into arrays, pre-multiplying constants, replacing division with reciprocal, eliminating ternaries with epsilons, or simplifying trace identities all consistently regress by 1-5%, likely disrupting the compiler's optimal instruction scheduling (`extract-inverse-c2` -4.4%, `replace-angle-divisions-with-inverse-magnitude` -2.6%, `factor-quarter-scaling-isotropic` -2.6%, `precompute-reciprocal-variance` -3.1%, `bake-half-factor-into-cos-sin` -4.5%, `pre-multiply-isotropic-kernel-constants` -3.3%, `eliminate-angle-ternary-with-epsilon` -0.9%, `simplify-b22-trace-identity` -0.8%).
- **Reordering memory access patterns or adding software prefetch:** Interleaving LF/HF neighbor loads (-3.5%) and adding `__builtin_prefetch` hints for strided row access (-6.0%) both regressed. The hardware prefetcher and out-of-order engine already handle these patterns adequately; manual intervention creates instruction overhead or cache pollution.
- **Reordering loops, phasing, or merging lightweight passes:** Swapping loop order, manually phasing logic into scoped blocks, or merging variance regularization into the output loop consistently fails (`swap-sums-angle-loop-order` +0.1%, `merge-variance-regularization` -3.2%, `phase-gradient-laplacian-into-scoped-blocks` -4.0%).
- **Eliminating local arrays the compiler already handles well:** Removing small, well-aligned stack arrays (center pixel arrays, sin²θ arrays) via direct computation or formula rewriting doesn't help — the compiler already maps these to vector registers (`eliminate-center-pixel-stack-arrays` +0.1%, `eliminate-sin-theta-sq-arrays` -0.5%, `eliminate-redundant-array-zeroing` -0.2%).
- **Manual loop unrolling or macro-specialization:** Peeling the first scale iteration, specializing fully isotropic pixels, or manually unrolling 4-iteration loops all fail to beat the compiler (`unroll-first-wavelet-scale` -0.3%, `specialize-fully-isotropic-pixel-body` -0.4%, `unroll-c2-exp-loop` +0.3% but missed 1% target).
- **Reusing local variables instead of global memory for unmodified data:** Reading center pixels from previously populated local arrays rather than via global pointer offsets severely regresses, suggesting register pressure increase or cache aliasing (`reuse-local-center-arrays` -7.0%).
- **Manual address arithmetic or inlining simple function calls:** Pre-multiplying loop indices (`pre-multiply-and-hoist-memory-offsets` -0.2%) and manually inlining functions like isotropic accumulation (`inline-isotropic-convolutions` +0.5%) provide no benefit — the compiler handles both optimally.
