## What works
- **Replacing intermediate stack arrays with native scalar variables:** Eliminating large array allocations within innermost loops reduces register spilling and L1 memory traffic (`strip-internal-array-allocations` ~11.9%, `compound-near-miss-optimizations` ~6.2%).
- **Exploiting mathematical symmetry to inline logic:** Leveraging spatial symmetries to inline convolutions algebraically reduces both operations and intermediate allocations (`inline-symmetric-convolutions` ~11.7%).
- **Nontemporal (streaming) stores for write-once buffers not read again soon:** Replacing normal stores avoids cache pollution for buffers that are not read immediately, like final output and HF writes (`nontemporal-hf-writes-in-decomposition` ~7.3%, `nontemporal-output-stores` ~1.3%).
- **Outer-loop unswitching that eliminates heavy per-pixel math:** Skipping expensive operations like sqrtf, divisions, trig math, or dt_vector_exp by evaluating binary conditions outside the pixel loop (`outer-loop-unswitch-isotropic-math` ~6.4%, `outer-unswitch-zero-speed-order-pairs` ~2.8%).
- **Compounding structurally related near-miss optimizations:** Grouping individual improvements that target the same bottleneck (e.g., stack array elimination) can compound gains significantly where they failed individually (`compound-near-miss-optimizations` ~6.2%).
- **Skipping entire passes via function-level guards:** Checking if a wavelet scale's contribution is negligible before calling PDE or allocating HF buffers saves entire passes without SIMD disruption (`skip-hf-decomposition-for-negligible-scales` ~5.0%, `skip-pde-negligible-norm` ~2.0%).
- **Pre-combining mathematical terms algebraically:** Pre-calculating combined terms (like LF+HF stencil sums) when parameters match, evaluated via outer-loop unswitching, halves convolution evaluations (`precombine-stencil-sums-for-matched-orders` ~3.0%).
- **Peeling loops to remove boundary clamping:** Splitting spatial loops into edge/center regions safely eliminates MAX/MIN instructions from the hot center path (`peel-column-loop-to-eliminate-clamping` ~2.4%).
- **Eliminating redundant math via algebraic absorption into constants:** Removing per-pixel scaling factors by absorbing them into loop-invariant pre-computed constants successfully reduces operations (`compute-cos2-sin2-directly` ~2.3%, `remove-0.5-scaling` ~1.5%).
- **Directly inlining generalized functions for fast paths:** Replacing generalized function calls with inline arithmetic for isotropic paths eliminates call overhead and switch branching (`inline-isotropic-convolutions` ~1.2%).

## What to avoid
- **Inlining expf or moving it between loops:** Changing when or where `expf`/`dt_vector_exp` is evaluated causes catastrophic regressions. The exp barrier between loop phases is load-bearing for compiler optimization (`inline-expf-evaluation-anisotropy` -170.9%, `inline-scalar-expf-fuse-all-pixel-passes` -114.4%, `Fused-angle-ex` -8.1%).
- **Skipping work based on dynamic runtime conditions inside the pixel loop:** Attempting to skip iterations, copy matched results, or bypass math based on runtime values inside the inner loop creates control flow dependencies that severely degrade SIMD performance (`skip-zero-speed-orders` -82.4%, `copy-matched-anisotropy-c2` -83.7%, `defer-symmetric-combinations` -91.7%).
- **Fusing distinct loops into massive single passes:** Combining too many operations into one loop drastically increases peak register pressure and destroys instruction scheduling (`pair-4-compute_convolution-calls` -48.7%, `fuse-variance-regularization-into-loading-loop` -8.2%, `inline-decomposition-horizontal-blur` -4.0%).
- **Outer-loop unswitching for trivial per-pixel savings:** Unswitching only works when it eliminates heavy math. When it merely removes a multiply, a mask load, or a lightweight check, icache bloat and code duplication negate any savings (`outer-loop-unswitch-matched-anisotropy` -17.1%, `outer-unswitch-zero-lf-contribution` -15.4%, `outer-unswitch-zero-sharpness` -13.1%).
- **Altering hardware-friendly memory access patterns:** Removing `dwt_interleave_rows` (-30.1%), unswitching row bounds (-26.7%), cache-blocking (-12.4%), or adding manual `__builtin_prefetch` hints (-6.0%) disrupts the hardware prefetcher and regresses performance.
- **Using nontemporal stores for buffers read soon after:** Nontemporal stores for buffers that are read on the very next scale pass cause massive regression because the data is evicted before it's needed (`nontemporal-lf-writes-in-decomposition` -68.8%).
- **Micro-optimizations to the existing hot-path algebra:** Extracting subexpressions, computing inverse magnitudes, applying fast-math approximations like `rsqrt`, or using explicit `fmaf` chains consistently disrupt optimal compiler instruction scheduling (`extract-inverse-c2` -4.4%, `bake-half-factor-into-cos-sin` -4.5%, `explicit-fmaf-variance-chain` -2.2%).
- **Reordering loops, phasing, or merging lightweight passes:** Swapping loop order, manually phasing logic into scoped blocks, or fusing full-image passes fails to provide gains and often increases register pressure (`phase-gradient-laplacian-into-scoped-blocks` -4.0%, `swap-sums-angle-loop-order` -3.2%).
- **Micro-optimizing buffer allocations or removing dead code:** Conditional deferral, pooling buffer allocations, freeing buffers early, or removing unused functions yields zero to negative improvement as overhead is negligible compared to pixel computation (`allocate-contiguous-hf-buffer-pool` -5.1%, `remove-dead-convolution-matrix-generators` -0.2%).
