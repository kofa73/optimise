## What works
- **Replacing intermediate stack arrays with native scalar variables:** Eliminating large array allocations within innermost loops reduces register spilling and L1 memory traffic (`strip-internal-array-allocations` ~11.9%, `compound-near-miss-optimizations` ~6.2%).
- **Exploiting mathematical symmetry to inline logic:** Leveraging spatial symmetries to inline convolutions algebraically reduces both operations and intermediate allocations (`inline-symmetric-convolutions` ~11.7%).
- **Outer-loop unswitching for simple, binary mathematical variants:** Evaluating a boolean condition outside the innermost loop to select fully specialized loop bodies safely skips heavy per-pixel math without SIMD-breaking branches (`outer-loop-unswitch-isotropic-math` ~6.4%).
- **Compounding structurally related near-miss optimizations:** Grouping individually marginal improvements that all reduce the same bottleneck (e.g., stack array elimination) into one unified change can compound gains (`compound-near-miss-optimizations` ~6.2%).
- **Eliminating redundant math via algebraic absorption into constants:** Removing per-pixel scaling factors by absorbing them into loop-invariant pre-computed constants successfully reduces operations (`remove-0.5-scaling` ~1.5%, `compute-cos2-sin2-directly` ~2.3%).
- **Skipping entire passes via function-level guards:** Checking if a wavelet scale's contribution is negligible before calling PDE or allocating HF buffers saves entire passes without SIMD disruption (`skip-hf-decomposition-for-negligible-scales` ~5.0%, `skip-pde-negligible-norm` ~2.0%).
- **Nontemporal (streaming) stores for write-once buffers not read again soon:** Replacing normal stores avoids cache pollution for buffers that are not read immediately (`nontemporal-hf-writes-in-decomposition` ~7.3%, `nontemporal-output-stores` ~1.3%).
- **Directly inlining generalized functions for fast paths:** Replacing generalized function calls with inline arithmetic for isotropic paths eliminates call overhead and switch branching (`inline-isotropic-convolutions` ~1.2%).
- **Peeling loops to remove boundary clamping:** Splitting spatial loops into edge/center regions safely eliminates MAX/MIN instructions from the hot center path (`peel-column-loop-to-eliminate-clamping` ~2.4%).

## What to avoid
- **Fusing distinct loops into massive single passes:** Combining too many operations into one loop drastically increases peak register pressure and destroys instruction scheduling (`inline-scalar-expf-fuse-all-pixel-passes` -114.4%, `pair-4-compute_convolution-calls` -48.7%).
- **Inlining expf or moving it between loops:** Changing when or where `expf`/`dt_vector_exp` is evaluated causes catastrophic regressions (`inline-expf-evaluation-anisotropy` -170.9%, `Fused-angle-ex` -8.1%).
- **Skipping work based on dynamic runtime conditions inside the pixel loop:** Attempting to skip iterations or math based on runtime values inside the inner loop creates control flow dependencies that severely degrade SIMD performance (`skip-zero-speed-orders` -82.4%, `copy-matched-anisotropy-c2` -83.7%).
- **Outer-loop unswitching beyond proven massive bottlenecks:** Unswitching consistently destroys compiler optimization or icache performance when the state is complex or savings are too small (`unswitch-row-bounds` -26.7%, `outer-unswitch-zero-lf-contribution` -15.4%, `peel-bspline-horizontal-decomposition` -16.7%).
- **Micro-optimizations to the existing hot-path algebra:** Extracting subexpressions, computing inverse magnitudes, or applying fast-math approximations like `rsqrt` consistently disrupt optimal compiler instruction scheduling (`extract-inverse-c2` -4.4%, `unify-isophote-and-gradient-math` -3.1%, `rsqrt-anisotropic-magnitude` -0.8%).
- **Eliminating local arrays the compiler already handles well:** Removing small, well-aligned stack arrays via direct computation or named scalars does not help and can regress (`replace-i-neighbours-array-with-scalars` -6.8%, `eliminate-redundant-array-zeroing` -0.2%).
- **Reordering memory access patterns, adding prefetch, or cache-blocking:** Interleaving neighbor loads, adding `__builtin_prefetch` hints, or cache-blocking loops regressed performance. The hardware prefetcher already handles these patterns optimally (`cache-block-pde-column-strips` -12.4%, `prefetch-interleaved-row-neighbors` -6.0%).
- **Reordering loops, phasing, or merging lightweight passes:** Swapping loop order, manually phasing logic into scoped blocks, or merging full-image passes fails to provide gains (`phase-gradient-laplacian-into-scoped-blocks` -4.0%, `fuse-consecutive-negligible-scale-additions` -0.5%).
- **Manual loop unrolling, address arithmetic, or macro-specialization:** Peeling iterations, manual unrolling, pre-multiplying loop indices, or reusing local arrays actively regresses or fails to beat the compiler (`unroll-first-wavelet-scale` -0.3%, `pre-multiply-and-hoist-memory-offsets` -0.2%, `reuse-local-center-arrays` -7.0%).
- **Hoisting allocations or restructuring buffer layout outside the hot loop:** Moving or deferring memory allocations, coalescing buffers, or removing dead code saves negligible time compared to per-pixel work and often introduces slight regressions (`allocate-contiguous-hf-buffer-pool` -5.1%, `hoist-tempbuf-allocation` +0.3%).
- **Using nontemporal stores for buffers read soon after:** Nontemporal stores for buffers (like LF/blur) that are read on the very next scale pass cause massive regression because the data is evicted before it's needed (`nontemporal-lf-writes-in-decomposition` -68.8%).
