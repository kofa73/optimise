## What works
- **Replacing intermediate stack arrays with native scalar variables:** Eliminating small array allocations within innermost loops reduces register spilling and L1 memory traffic (e.g., `strip-internal-array-allocations-for-find_gradients-normalizations` yielded ~11.9% improvement).
- **Exploiting mathematical symmetry to inline logic:** Leveraging spatial symmetries to inline convolutions algebraically (instead of expanding kernels into large arrays) reduces operations and intermediate allocations (e.g., `inline-symmetric-convolutions` yielded ~11.7% improvement).
- **Outer-loop unswitching for simple mathematical variants:** Evaluating conditions outside innermost loops safely skips heavy per-pixel math without introducing SIMD-breaking branches (e.g., bypassing angle math for isotropic orders in `001-outer-loop-unswitch-isotropic-math` yielded ~6.4% improvement).
- **Compounding multiple near-miss optimizations:** Grouping structurally related minor improvements (like inline accumulation, scalar memory offsets, and skipping redundant math) into a single unified loop simplification can successfully cross benchmark thresholds (`2026-03-16-00-01-55-compound-near-miss-optimizations` yielded ~6.2% improvement).
- **Fetching specific pixels inline via direct memory offsets:** Fetching pixels directly from source pointers via pre-computed offsets is faster than bulk copying into intermediate stack-allocated matrices.

## What to avoid
- **Fusing distinct loops into massive single passes:** Combining too many operations into one channel loop drastically increases peak register pressure and destroys instruction scheduling (e.g., `2026-03-16-11-24-58-inline-scalar-expf-fuse-all-pixel-passes` regressed by -114.4%, and `010-pair-4-compute_convolution-calls-into-2-for_each_channel-loops` regressed by -48.7%).
- **Skipping heavy work based on dynamic/complex conditions:** Attempting to skip loop iterations or math based on speeds/anisotropy matches creates control flow or data dependencies that severely degrade performance (e.g., `010-skip-zero-speed-orders` regressed by -82.4%, `099-copy-matched-anisotropy-c2-to-skip-expf` regressed by -83.7%).
- **Deferring math or using scoped blocks to reduce live variables:** Restructuring logic purely to limit live arrays often introduces cache overhead or redundant L1 reads that outweigh the register benefits (e.g., `2026-03-17-21-48-08-defer-symmetric-combinations-to-eliminate-stack-arrays` regressed by -91.7%, `2026-03-16-07-58-50-phase-gradient-laplacian-into-scoped-blocks` regressed by -4.0%).
- **Outer-loop unswitching for large complex macros:** Duplicating the entire main row loop via macros to avoid a single simple condition (like `has_mask`) disrupts compiler optimizations (e.g., `026-03-17-21-54-49-outer-loop-unswitch-has-mask` regressed by -3.5%).
- **Minor mathematical simplifications without memory reduction:** Stripping constant scaling factors or substituting basic algebraic identities alone fails to reach performance targets. The inner loop is memory/register bounded, so saving a few ALU operations yields negligible gains (e.g., `000-eliminate-gradient-halving`, `010-simplify-b22-trace-identity`).
- **Removing explicit loop array zeroing:** Eliminating `{ 0.f }` array initializations inside pixel loops surprisingly degrades performance, likely because it disrupts vectorization or compiler assumptions (e.g., `026-03-17-22-13-06-eliminate-redundant-array-zeroing` regressed by -2.2%).
- **Peeling loops to remove clamping:** Extracting center loops to avoid bounds clamping (`MAX`/`MIN`) fails to improve performance, as modern branch prediction and SIMD handle basic clamps efficiently (e.g., `026-03-17-22-28-33-peel-column-loop-to-eliminate-clamping`).
- **Merging lightweight output loops with heavy operations:** Combining simple passes with heavier logic disrupts the optimization of the simple loop without reducing overall latency (e.g., `000-merge-variance-regularization-into-output-loop` regressed by -2.4%).
- **Simple loop reordering:** Swapping loop orders (e.g., sums vs. angle loops) without a corresponding reduction in memory or register usage fails to improve performance (e.g., `013-swap-sums-angle-loop-order`).
- **Complex mathematical fusions and direct derivations:** Fusing trig/exponentials or deriving angles directly from squared gradients rather than normalized magnitudes increases critical path dependencies and underperforms (e.g., `002-Fused-angle-ex`, `002-compute-cos2-sin2-cos-sin-directly`).
