## What works
- **Replacing intermediate stack arrays with native scalar variables:** Eliminating array allocations within innermost loops reduces register spilling and L1 memory traffic. This is the single most reliable optimization lever (`strip-internal-array-allocations` ~11.9%, `compound-near-miss-optimizations` ~6.2%).
- **Exploiting mathematical symmetry to inline logic:** Leveraging spatial symmetries to inline convolutions algebraically (instead of expanding kernels into arrays) reduces both operations and intermediate allocations (`inline-symmetric-convolutions` ~11.7%).
- **Outer-loop unswitching for simple, binary mathematical variants:** Evaluating a single boolean condition outside the innermost loop to select between fully specialized loop bodies safely skips heavy per-pixel math without SIMD-breaking branches (`outer-loop-unswitch-isotropic-math` ~6.4%). Only works when the skipped work is massive.
- **Compounding multiple structurally related near-miss optimizations:** Grouping 2-3 individually marginal improvements that all reduce the same bottleneck (stack arrays / memory traffic) into one unified change successfully compounds gains (`compound-near-miss-optimizations` ~6.2%).
- **Eliminating redundant math via algebraic absorption into pre-computed constants:** Removing per-pixel scaling factors by absorbing them into loop-invariant constants works when it genuinely eliminates operations rather than just reshuffling them (`remove-0.5-scaling` ~1.5%, `compute-cos2-sin2-directly` ~2.3%).
- **Skipping entire passes via function-level guards:** Checking whether a wavelet scale's contribution is negligible (Gaussian norm near zero) before calling `heat_PDE_diffusion` or allocating HF buffers saves entire passes for irrelevant scales (`skip-pde-negligible-norm` ~2.0%, `skip-hf-decomposition-for-negligible-scales` ~5.0%). Works because the check is at function-call level, avoiding SIMD disruption.
- **Nontemporal (streaming) stores for write-once buffers not read again soon:** Replacing normal stores with nontemporal writes avoids write-allocate cache pollution. Works for HF detail writes during bspline decomposition (~7.3%) and PDE output (~1.3%). **Critical:** the buffer must not be read again until a substantially later pass — nontemporal stores for LF/blur buffers that ARE read on the very next scale pass caused catastrophic -68.8% regression because data was evicted before needed.
- **Directly inlining isotropic convolution math to bypass generalized function:** Replacing the function call to `accumulate_convolution_direct` (which hits a runtime switch) with direct inline arithmetic for isotropic paths eliminates function call overhead, dummy array initialization, and switch branching (`inline-isotropic-convolutions` ~1.2%).
- **Peeling the PDE column loop to remove boundary clamping:** Splitting the column loop into edge/center regions eliminates MAX/MIN from the hot center path (`peel-column-loop` ~2.4%).

## What to avoid
- **Fusing distinct loops into massive single passes:** Combining too many operations into one channel loop drastically increases peak register pressure and destroys instruction scheduling (`inline-scalar-expf-fuse-all-pixel-passes` -114.4%, `pair-4-compute_convolution-calls` -48.7%, `defer-symmetric-combinations` -91.7%).
- **Inlining expf or moving it between loops:** Any attempt to change when/where `expf`/`dt_vector_exp` is evaluated causes catastrophic regression (`inline-expf-evaluation-anisotropy` -170.9%, `Fused-angle-ex` -8.1%). The compiler's current placement is optimal.
- **Skipping work based on dynamic runtime conditions inside the pixel loop:** Attempting to skip iterations or math based on runtime values (speeds, anisotropy matches) creates control flow or data dependencies that severely degrade SIMD performance (`skip-zero-speed-orders` -82.4%, `copy-matched-anisotropy-c2` -83.7%).
- **Outer-loop unswitching beyond the one proven case:** Code duplication from unswitching consistently destroys compiler optimization or icache performance when the state is complex (`matched-anisotropy` -17.1%, `unswitch-row-bounds` -26.7%) or savings are too small (`has_mask` -3.5%, `outer-unswitch-zero-sharpness` -13.1%, `outer-unswitch-zero-lf-contribution` -15.4%). Peeling the B-spline horizontal decomposition pass also caused massive regression (-16.7%).
- **Micro-optimizations to the existing hot-path algebra:** Extracting common subexpressions, computing inverse magnitudes, baking factors into arrays, pre-multiplying constants, simplifying trace identities, or conditionally swapping axis sums consistently regress by 1-5%, likely disrupting the compiler's optimal instruction scheduling (`extract-inverse-c2` -4.4%, `unify-isophote-and-gradient-math` -3.1%, `pre-multiply-isotropic-kernel-constants` -3.3%, `replace-angle-divisions-with-inverse-magnitude` -2.6%).
- **Eliminating local arrays the compiler already handles well:** Removing small, well-aligned stack arrays (center pixel arrays, sin²θ arrays, 3-element index arrays) via direct computation or named scalars doesn't help and can severely regress (`eliminate-center-pixel-stack-arrays` +0.1%, `eliminate-sin-theta-sq-arrays` -0.5%, `replace-i-neighbours-array-with-scalars` -6.8%).
- **Reordering memory access patterns, adding prefetch, or cache-blocking:** Interleaving LF/HF neighbor loads (-3.5%), adding `__builtin_prefetch` hints (-6.0%), and cache-blocking into vertical column strips (-12.4%) all regressed. The hardware prefetcher already handles these patterns adequately.
- **Reordering loops, phasing, or merging lightweight passes:** Swapping loop order, manually phasing logic into scoped blocks, or merging full-image passes consistently fails to provide gains (`merge-variance-regularization` -3.2%, `phase-gradient-laplacian-into-scoped-blocks` -4.0%, `fuse-build-mask-and-inpaint-mask` +0.5%).
- **Manual loop unrolling, macro-specialization, or algebraic call-count reduction:** Peeling iterations, specializing fully isotropic pixels, manually unrolling loops, or halving calls algebraically all fail to beat the compiler (`unroll-first-wavelet-scale` -0.3%, `specialize-fully-isotropic-pixel-body` -0.4%, `combine-isotropic-abcd-coefficients` -0.1%).
- **Hoisting allocations, reducing memory lifetime, or restructuring buffer layout outside the hot loop:** Moving buffer allocations/frees, deferring unused allocations, coalescing separate allocations into contiguous pools, removing dead clamping, removing dead code, or pre-computing parameters save negligible time compared to per-pixel work and often regress (`allocate-contiguous-hf-buffer-pool` -5.1%, `hoist-tempbuf-allocation` +0.3%, `defer-unused-image-buffer-allocations` +0.0%, `free-hf-buffers-after-reconstruction` -0.1%, `remove-dead-convolution-matrix-generators` -0.2%).
- **Manual address arithmetic or local variable reuse:** Pre-multiplying loop indices (`pre-multiply-and-hoist-memory-offsets` -0.2%) or reading center pixels from previously populated local arrays instead of global pointers (`reuse-local-center-arrays` -7.0%) actively regress.
