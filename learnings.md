## What works
- **Replacing intermediate stack arrays with native scalar variables:** Eliminating small array allocations within innermost loops reduces register spilling and L1 memory traffic (e.g., `strip-internal-array-allocations-for-find_gradients-normalizations` yielded ~11.9% improvement).
- **Exploiting mathematical symmetry to inline logic:** Leveraging spatial symmetries to inline convolutions algebraically (instead of expanding kernels into large arrays) reduces operations and intermediate allocations (e.g., `inline-symmetric-convolutions` yielded ~11.7% improvement).
- **Outer-loop unswitching for simple mathematical variants:** Evaluating conditions outside innermost loops safely skips heavy per-pixel math without introducing SIMD-breaking branches (e.g., bypassing angle math for isotropic orders in `001-outer-loop-unswitch-isotropic-math` yielded ~6.4% improvement).
- **Compounding multiple near-miss optimizations:** Grouping structurally related minor improvements (like inline accumulation, scalar memory offsets, and skipping redundant math) into a single unified loop simplification successfully compounds efficiency gains (e.g., `2026-03-16-00-01-55-compound-near-miss-optimizations` yielded ~6.2% improvement).
- **Fetching specific pixels inline via direct memory offsets:** Fetching pixels directly from source pointers via pre-computed offsets is faster than bulk copying into intermediate stack-allocated matrices (successfully applied).

## What to avoid
- **Fusing distinct loops into massive single passes:** Combining too many operations into one channel loop drastically increases peak register pressure and destroys instruction scheduling (e.g., `inline-scalar-expf-fuse-all-pixel-passes` regressed -114.4%, `pair-4-compute_convolution-calls` regressed -48.7%).
- **Skipping heavy work based on dynamic/complex conditions:** Attempting to skip loop iterations or math based on speeds or anisotropy matches creates control flow or data dependencies that severely degrade performance (e.g., `skip-zero-speed-orders` regressed -82.4%, `copy-matched-anisotropy-c2` regressed -83.7%).
- **Deferring math or using scoped blocks to reduce live variables:** Restructuring logic purely to limit live arrays often introduces cache overhead or redundant L1 reads that outweigh the register benefits (e.g., `defer-symmetric-combinations-to-eliminate-stack-arrays` regressed -91.7%).
- **Eliminating local arrays that already map to vector registers well:** Removing stack arrays via direct computation or rewriting formulas actually degraded performance, suggesting the compiler optimally handles them (e.g., `eliminate-center-pixel-stack-arrays` regressed -2.2%, `eliminate-sin-theta-sq-arrays` regressed -2.2%, `bake-half-factor-into-cos-sin` regressed -4.5%).
- **Common subexpression elimination in the hot path:** Extracting variables like `1.0f - c2` or inverse magnitude actually decreases performance, likely disrupting vectorization or pipelining (e.g., `extract-inverse-c2-subexpression` regressed -4.4%, `replace-angle-divisions-with-inverse-magnitude` regressed -2.6%).
- **Pre-computing or pre-modifying constants:** Pre-negating anisotropy, pre-computing reciprocal variance, or pre-multiplying kernel constants unexpectedly regresses performance, possibly by disrupting optimal instruction generation (e.g., `pre-negate-anisotropy-constants` failed, `precompute-reciprocal-variance` regressed -3.1%, `pre-multiply-isotropic-kernel-constants` regressed -3.3%).
- **Minor mathematical simplifications without memory reduction:** Stripping constant scaling factors (like `0.5f`) or substituting basic algebraic identities yields negligible gains and sometimes regresses because the inner loop is memory/register bounded (e.g., `eliminate-gradient-halving` failed, `simplify-b22-trace-identity` regressed -2.6%).
- **Tricks to bypass conditionals or unswitch complex macros:** Trying to unswitch `has_mask` or force isotropic paths via parameter overrides or epsilon addition degrades performance (e.g., `outer-loop-unswitch-has-mask` regressed -3.5%, `force-isotropic-path-for-zero-speed` regressed -3.4%, `eliminate-angle-ternary-with-epsilon` regressed -2.3%).
- **Removing explicit loop array zeroing:** Eliminating `{ 0.f }` array initializations inside pixel loops degrades performance, likely disrupting compiler vectorization assumptions (e.g., `eliminate-redundant-array-zeroing` regressed -2.2%).
- **Peeling loops to remove clamping:** Extracting center loops to avoid bounds clamping (`MAX`/`MIN`) fails to improve performance as modern branch prediction handles it efficiently (e.g., `peel-column-loop-to-eliminate-clamping` failed).
- **Merging lightweight output loops with heavy operations:** Combining simple passes with heavier logic disrupts the optimization of the simple loop (e.g., `merge-variance-regularization-into-output-loop` regressed -2.4%).
