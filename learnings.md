## What works
- **Massive operation count reduction via mathematical symmetry:** `inline-symmetric-convolutions` exploited kernel spatial symmetry to cut multiplications from 36 to 16 per channel (~11.7% improvement). The key: identify redundant arithmetic across symmetric data and algebraically eliminate it, achieving >50% reduction in a hot section.
- **Replacing intermediate arrays with scalar variables:** `strip-internal-array-allocations` replaced small fixed-size intermediary arrays with individual scalars, yielding ~11.9% improvement. This helps the compiler use registers instead of spilling to stack.
- **Both successes share a pattern: large reduction in per-pixel work inside the innermost loop.** Small savings per pixel compound across millions of pixels. But the reduction must be substantial (>50% of a subsection) to cross the 5% threshold.
- **Preserving bit-identical floating-point evaluation order is a hard prerequisite.** Any change to multiply-accumulate sequencing causes benchmark errors or subtle regressions.
- **Near-miss optimizations cluster at +2-4%:** Eliminating neighbor arrays via offset access (+2.6% to +4.0%), inlining derivative accumulation (+3.3%), and skipping `expf` for isotropic orders (+3.2%) all showed real but insufficient improvement individually. Multiple near-miss ideas might compound if combined carefully.

## What to avoid
- **Over-merging loops / pairing function calls:** Grouping `compute_convolution` calls into fewer shared loops caused -48.7% regression (`pair-4-calls`). Increased register pressure and broken vectorization far outweigh loop overhead savings.
- **Pre-combining kernel data before convolution:** `fuse-paired-kernel-convolutions` altered floating-point evaluation order by combining kernels, causing benchmark error. Even mathematically equivalent reorderings break bit-exactness.
- **Restructuring code without reducing total operation count:** `Fused-angle-ex` fused angle and exponential computations without eliminating any operations, causing -8.1% regression. Code reorganization alone cannot beat the compiler.
- **Conditional branching to skip work:** `copy-matched-anisotropy-c2-to-skip-expf` (-1.1%) and `skip-zero-speed-orders` (-1.0%) both regressed despite skipping expensive `expf` calls. Branches disrupt SIMD vectorization, and the skipped work is a small fraction of total cost.
- **Algebraic micro-substitutions:** Replacing `a[0][0] + a[1][1]` with `1.0f + c2` via trig identity (`simplify-b22-trace-identity`, +2.2%) doesn't cross the threshold. Single-instruction savings are dwarfed by memory/cache costs.
- **Rewriting array construction without reducing total work:** `rewrite-9-element-kernel-matrix-instantiation` inlined kernel matrix construction but showed no improvement — same number of values still computed and stored.
- **Eliminating neighbor pixel arrays alone is not enough:** Direct memory fetches with offsets (`inline-neighbor-pixel-access` +4.0%, `eliminate-intermediate-stack-arrays` +2.6%) give modest improvement but don't reach the 5% threshold. The neighbor copy is not the dominant cost.
