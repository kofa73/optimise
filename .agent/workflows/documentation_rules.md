# Documentation Rules

## 1. Keep Documentation Updated
- Whenever you make changes to the codebase that affect architecture, configurations, commands, or user workflows, you **MUST** systematically update the relevant files in the `docs/` directory and the `README.md`.
- Never leave out-of-date documentation behind after implementing new features. Documentation maintenance is part of the feature completion process.

## 2. Use Dry, Technical Language
- Always use down-to-earth, precise, and highly technical language in documentation.
- **DO NOT** use "fancy marketing" language, buzzwords, or overly dramatic adjectives (e.g., avoid descriptive filler words like "vigorously", "protective", "pristine", "seamlessly", "magical").
- Focus strictly on facts, clear instructions, and objective descriptions of the system mechanisms.
