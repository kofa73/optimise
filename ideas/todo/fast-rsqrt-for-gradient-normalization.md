Use fast reciprocal square root for gradient direction normalization

The hot loop calls sqrtf() twice per pixel to compute gradient and laplacian magnitudes, then immediately divides each component by the magnitude to normalize. This pattern (sqrt then divide) can be replaced by a single fast reciprocal square root (rsqrt) followed by multiplication: instead of mag = sqrtf(dx*dx+dy*dy); nx = dx/mag, compute inv_mag = rsqrtf(dx*dx+dy*dy); nx = dx*inv_mag. Modern compilers can map rsqrtf to single-instruction SIMD operations (rsqrtss/rsqrtps on x86, vrsqrte on ARM) which are significantly faster than sqrtf+division. The c2 anisotropy weight (-magnitude * anisotropy) can be rewritten as (-1/inv_mag * anisotropy). Since exact precision is unnecessary for directional weighting in a PDE solver, the ~1e-3 relative error of hardware rsqrt is acceptable.
