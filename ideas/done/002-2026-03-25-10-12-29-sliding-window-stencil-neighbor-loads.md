perf: apply register-based sliding window to LF and HF neighbor memory fetches

The PDE convolution currently fetches all 9 neighbor pixels from L1 cache for every pixel evaluated. Because the spatial loop processes pixels linearly across a row, the left and center columns of the current pixel perfectly overlap with the center and right columns of the previous pixel. By carrying these columns forward in registers to the next loop iteration, we can reduce the inner-loop memory loads from 9 to 3 per layer (fetching only the new right column). This drastically cuts L1 bandwidth and allows the stencil sums to be computed incrementally.
outcome: not applicable

The proposed register-based sliding window assumes that the left and center columns of the current pixel perfectly overlap with the center and right columns of the previous pixel. This is only true for a standard non-dilated convolution where the column step is 1. However, the PDE step uses a dilated (à trous) wavelet convolution where `col_step = mult * H` (which doubles with each wavelet scale). Because the spatial loop processes adjacent pixels linearly (`j++`) to maximize hardware L1 prefetching, the 3x3 stencils of consecutive pixels do not overlap at all for any scale where `mult > 1`. Therefore, carrying columns forward in registers between consecutive loop iterations is mathematically infeasible.
