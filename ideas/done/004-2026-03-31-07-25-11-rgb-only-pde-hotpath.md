perf: split RGB diffusion from passthrough alpha in the CPU PDE loops

If the fourth channel is only carried through as opacity/alpha, keep it out of the gradient, variance, and convolution helpers and copy it only at stage boundaries. That reduces arithmetic and temporary-buffer traffic across the hottest loops by roughly a quarter for RGBA images, and it can be implemented cleanly with shared 3-channel inline helpers plus a simple passthrough path for channel 3.

outcome: not applicable

The optimization idea is not applicable because the entire pixel processing pipeline in `diffuse.c` is built on 4-channel SIMD processing, making the 4th channel computation essentially free:

1. **`for_each_channel` iterates over `DT_PIXEL_SIMD_CHANNELS` = 4** (when vectorization is enabled), and is decorated with `#pragma omp simd`. This means each `for_each_channel` loop compiles to single-width SSE/AVX instructions (`addps`, `mulps`, `sqrtps`, etc.) that process all 4 channels in one operation. Processing 3 channels costs the same as 4.

2. **`copy_pixel_nontemporal` uses `_mm_stream_ps`**, which inherently operates on 128-bit (4-float) units. There's no way to write only 3 channels.

3. **`dt_vector_exp`** is explicitly vectorized for 4-float vectors. No savings from 3 channels.

4. **All buffer allocation and stride calculations** assume 4 floats per pixel (`index = idx * 4`, `j * 4`, etc.). Changing to 3-channel buffers would require restructuring the entire wavelet decomposition, reconstruction, and B-spline infrastructure.

5. **The learning history confirms this pattern**: attempts to scalarize or restructure the SIMD data flow caused catastrophic regressions (e.g., `explicit-scalarization-of-accumulation-arrays` at -111.8%).

The 4th channel is processed for free as a SIMD lane fill — splitting it out would either keep full-width SIMD (no savings) or break vectorization (regression).
